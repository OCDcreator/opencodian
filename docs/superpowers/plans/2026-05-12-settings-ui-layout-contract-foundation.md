# Settings UI Layout Contract Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the foundation of the settings UI layout contract: settings-local design tokens, section inventory docs, structural shell normalization, and shared section / ordinary setting row styling for both `classic` and `tabbed` modes.

**Architecture:** This plan covers Slice 0-2 from `docs/superpowers/specs/2026-05-12-settings-ui-layout-contract-design.md`. It keeps all settings behavior unchanged, adds a dedicated settings CSS contract module, maps existing DOM classes to shared surface tokens, and makes the tabbed content shell structural instead of a heavy card. Object-heavy areas such as MCP, model availability, formatter runtime rows, agents, commands, plugins, and style preview cards remain for later per-owner plans.

**Tech Stack:** TypeScript, Obsidian `Setting`, Jest/jsdom, CSS custom properties, existing `src/style` CSS merge pipeline.

---

## Scope Boundaries

This plan implements only the foundation:

- In scope: settings token contract, CSS module, shared section block styling, light setting-row card styling, tabbed shell normalization, tests, module docs, build verification.
- Out of scope: semantic behavior changes, settings migration changes, new settings, removing either layout mode, full MCP/model/formatter/style object-card migration, external design libraries.
- Required preservation: `settingsLayoutMode`, `settingsTabbedPrimaryTab`, `settingsTabbedSecondaryTabByPrimary`, classic quick nav, classic scroll restoration, dropdown enhancement, editor-area settings view, modals.

```markdown
# settings-layout-contract.css

> **源码**: `src/style/components/settings-layout-contract.css`

## Purpose

Owns the shared settings UI layout contract for both classic and tabbed settings modes.

This module defines settings-local CSS tokens for section surfaces, ordinary setting rows, object surfaces, inline groups, radius, spacing, and basic typography. It maps existing settings DOM classes onto the shared surface hierarchy without changing settings behavior.

## Surface Contract

- `.opencodian-settings-content-shell`: structural tabbed/classic content wrapper.
- `.opencodian-settings-section`: semantic section block marker emitted by settings chrome.
- `.opencodian-settings-block`: existing section block class preserved for compatibility.
- `.setting-item` inside `.opencodian-settings-section`: ordinary setting row card.

## Guardrails

- Keep tokens derived from Obsidian theme variables.
- Do not style chat, composer, or non-settings surfaces from this module.
- Do not create heavy card nesting. Nested content inside a section must use lighter row, inline, toolbar, or metadata surfaces.
```
