# OpenCodian 架构总览

> 本文档面向想要了解 OpenCodian 内部运作方式的开发者，用通俗易懂的语言解释各个模块的功能和它们之间的关系。

---

## 一句话概括

OpenCodian 是一个 Obsidian 插件，它在 Obsidian 侧边栏里嵌入了一个 AI 聊天界面，通过 OpenCode SDK v2 与 legacy HTTP/SSE 双路径和后台 OpenCode 服务通信，再由 OpenCode 调用各种 AI 模型（Claude、GPT、本地模型等）来完成对话。

## 核心组件详解

### 1. 插件入口 — `main.ts`

**角色**：整个插件的"总指挥"。

**职责**：
- 加载和保存设置
- 初始化所有服务（存储、通信、配置）
- 注册 Obsidian 视图、命令、侧边栏图标
- 管理会话列表的生命周期

**初始化顺序**（`onload` 方法中）：

```
1. StorageService    → 准备存储目录
2. loadSettings()    → 读取用户配置
3. setLocale()       → 设置界面语言
4. OpenCodeService   → 创建 HTTP 客户端
5. OpencodeConfigMgr → 读取 OpenCode 配置
6. ModelConfigService→ 准备模型目录
7. 注册 View         → 创建聊天界面
8. 注册 Settings     → 创建设置面板
9. 注册 Commands     → 注册快捷命令
```

---

### 2. 后端通信 — `OpenCodeService`

**角色**：插件与 OpenCode 服务器之间的"翻译官"。

**职责**：
- 创建/删除聊天会话
- 发送用户消息并接收流式回复
- 获取目录作用域下的 AI 模型列表与解析配置
- 在设置页里执行 provider 真实发送探针
- 管理会话标题

**核心工作流程** — 用户发送一条消息：

```
用户输入文字
    ↓
OpenCodeService.sendMessage()
    ↓
优先走 SDK v2；失败或未启用时回退到 legacy HTTP/SSE
    ↓
服务器返回 SSE 事件流（文本块、思考过程、工具调用...）
    ↓
逐块解析并传回界面层渲染
    ↓
收到 "done" 事件 → 流结束
```

**关键方法一览**：

| 方法 | 作用 |
|------|------|
| `createSession(title?)` | 创建新的聊天会话 |
| `sendMessage(msg, opts)` | 发消息，拿到流式响应 |
| `requestAssistantResponse(msg, opts)` | 发消息，等完整回复（非流式） |
| `getAvailableModels()` | 获取当前目录作用域下 runtime 可用模型 |
| `getResolvedModelConfig()` | 获取当前目录或默认作用域解析后的模型配置 |
| `probeProviderResponse()` | 用临时 session 探测 provider 是否真能发请求 |
| `getSessionMessages(id)` | 获取某个会话的所有消息 |
| `updateSessionTitle(id, title)` | 修改会话标题 |
| `deleteSession(id)` | 删除会话 |
| `forkSession(id, msgId?)` | 从某条消息分叉出新会话 |
| `revertSession(id, msgId, partId?)` | 回退会话到某个时间点 |

---

### 3. 服务器管理 — `ServerManager`

**角色**：OpenCode 服务器进程的"保姆"。

**职责**：
- 启动/停止 OpenCode 服务器进程
- 检测端口是否被占用
- 健康检查（确认服务器在响应）
- 崩溃恢复

**两种模式**：

| 模式 | 说明 |
|------|------|
| **本地模式** (`local`) | 插件自己启动 OpenCode 进程，管理其生命周期 |
| **远程模式** (`remote`) | 连接到已运行的远程服务器，只需配置地址和认证 |

**启动流程**（本地模式）：

```
ServerManager.start()
    ↓
检查端口是否可用
    ↓
启动 OpenCode 子进程
    ↓
循环健康检查（最多等 30 秒）
    ↓
服务器就绪 → 通知上层服务
```

---

### 4. 模型配置 — `ModelConfigService` + `OpencodeConfigManager`

**角色**：管理"可以用哪些 AI 模型"这件事。

**现在是三层来源协同**：

```
┌──────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 当前项目配置文件   │   │ 当前目录 runtime 列表 │   │ 继承层 / 默认作用域配置 │
│ .opencode/        │   │ config.providers()   │   │ config.get() / 本机磁盘 │
│ opencode.json     │   │                      │   │                      │
└────────┬─────────┘   └──────────┬───────────┘   └──────────┬───────────┘
         │                        │                            │
         └──────────────┬─────────┴──────────────┬─────────────┘
                        │                        │
                        ▼                        ▼
                server / local catalog     provider 继承规则
                        └──────────────┬──────────────┘
                                       ▼
                        baseEffective / effective catalog
```

- **`OpencodeConfigManager`**：读写 `.opencode/opencode.json` 文件，管理项目级配置（包括权限模式）
- **`ModelConfigService`**：把项目配置、当前目录 runtime providers 和继承层 provider 配置拼成 `local / server / baseEffective / effective` 四套视图，并额外给设置页提供“当前真正启用的 provider 列表”和真实发送 probe 结果

**权限模式**（由 OpencodeConfigManager 管理）：

| 模式 | 行为 |
|------|------|
| `yolo` | 允许所有操作，不询问 |
| `normal` | 每次操作都要用户确认 |
| `plan` | 只允许读取，禁止写入 |

### 5. 数据存储 — `StorageService`

**角色**：插件的"文件柜"。

**存储位置**：`.obsidian/plugins/opencodian/.opencodian/`

```
.opencodian/
├── settings.json          ← 插件设置
└── sessions/
    ├── conv-abc123.json   ← 会话 A 的数据
    └── conv-def456.json   ← 会话 B 的数据
```

**存储内容**：
- 插件设置（服务器地址、模型偏好、语言等）
- 会话元数据（标题、创建时间、最后消息时间）
- 完整会话数据（元数据 + 所有聊天消息）

### 7. 流式渲染 — `StreamController`

**角色**：把 AI 的实时响应"翻译"成屏幕上的文字和控件。

**工作原理**：

AI 的回复不是一次性返回的，而是一块一块地"流"过来的。StreamController 接收这些"块"，根据类型分发给不同的渲染器：

```
OpenCode 服务器返回 SSE 事件流
    ↓
    ├─ "text" 块        → 直接追加文字到消息区
    ├─ "thinking" 块    → ThinkingBlockRenderer 画思考过程
    ├─ "tool_use" 块    → ToolCallRenderer 画工具调用
    ├─ "tool_result" 块 → ToolCallRenderer 画工具结果
    ├─ "error" 块       → 显示错误信息
    └─ "done" 块        → 标记流结束
```

### 8. AI 标题生成 — `TitleGenerationService`

**角色**：给新对话起一个简短贴切的名字。

**工作流程**：

```
用户发送第一条消息
    ↓
TitleGenerationService.generateTitle()
    ↓
创建一个临时 OpenCode 会话
    ↓
把用户消息发给 AI，附带标题生成提示词
    ↓
AI 返回 ≤50 字的标题
    ↓
删除临时会话（不污染历史记录）
    ↓
更新当前会话标题
```

**配置选项**：
- `titleMode`：`default`（用默认标题）或 `ai`（用 AI 生成）
- `aiTitleModel`：可以指定用哪个模型生成标题（格式：`provider/model`），留空则跟随当前会话模型
- `locale`：标题语言（`zh` → 中文，`en` → 英文）

### 9. Markdown 渲染 — `MarkdownRenderService`

**角色**：让聊天消息好看、可交互。

**增强功能**（在 Obsidian 原生渲染基础上）：

| 功能 | 说明 |
|------|------|
| 图片嵌入 | 把 `![[image.png]]` 转为真实图片显示 |
| 文件链接 | 让 `[[_note]]` 变成可点击跳转的链接 |
| 代码块 | 添加语言标签和一键复制按钮 |
| 折叠长内容 | 超长的 AI 回复自动折叠，点击展开 |

### 10. 多标签系统 — `TabManager` + `Tab` + `TabBar`

**角色**：像浏览器标签一样管理多个聊天会话。

**组件分工**：

### 12. 安全模块 — `BlocklistChecker`

**角色**：防止 AI 执行危险命令的"安全卫士"。

**工作方式**：
- 维护一个命令黑名单（用户在设置中配置）
- 当 AI 尝试执行 bash 命令时，检查是否匹配黑名单
- 匹配方式：大小写不敏感的正则表达式，匹配失败时回退到子串匹配

**角色**：让界面支持多种语言。

## 关键设计决策

### 为什么选择客户端/服务器架构？

OpenCode 本身就是一个独立的服务器程序。OpenCodian 不重新实现 AI 交互逻辑，而是作为"前端"复用 OpenCode 的能力。这样：
- AI 功能的更新只需升级 OpenCode，插件代码不用改
- 用户可以使用 OpenCode 支持的所有模型提供商
- 服务器可以独立运行在远程机器上

同时插件保留了 SDK v2 主链路与 legacy HTTP/SSE 回退链路：前者更贴近 OpenCode 的新接口面，后者保证 rollout 期间的兼容和故障回退。

### 为什么使用 SSE 流式传输？

大语言模型的回复通常很长，如果等全部生成完再显示，用户需要面对长时间的空白。SSE（Server-Sent Events）让每个文字块一生成就立即传到前端显示，用户体验更流畅。

### 为什么标题生成用临时会话？

标题生成不需要保留上下文，只需把用户的第一条消息发给 AI 即可。使用临时会话可以：
- 不污染用户的历史会话列表
- 不消耗会话的上下文窗口
- 生成完立即清理，不留垃圾数据

## 常见问题

### Q: OpenCode 服务器是怎么启动的？

在"本地模式"下，`ServerManager` 会用 Node.js 的 `child_process` 启动 `opencode` 命令，然后在后台循环调用健康检查接口，直到服务器就绪。

### Q: 消息是怎么持久化的？

`StorageService` 使用 Obsidian 提供的文件系统 API（`Vault.adapter`）把会话数据写成 JSON 文件。每次发送消息或收到回复后都会自动保存。

### Q: 多标签是怎么实现的？

每个标签对应一个会话 ID（`sessionId`）。切换标签时，`OpenCodianView` 会：
1. 保存当前标签的输入框内容和滚动位置
2. 从 `StorageService` 加载目标会话的消息
3. 重新渲染消息列表
4. 恢复输入框内容和滚动位置

### Q: 如何添加新的 AI 功能？

1. 在 `core/prompts/` 下添加系统提示词
2. 在 `features/chat/services/` 下创建服务类
3. 在 `OpenCodianView` 中引入并调用
4. 在 `i18n/locales/` 中添加界面文本
