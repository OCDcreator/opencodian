# Task safety incident record

On 2026-11-08, the Pi/ZCode UI implementation subagent reported one prohibited shell cleanup during test debugging. It ran a compound command in `/Users/dht/zcode-worktrees/opencodian/backend-settings-refresh` that created `tests/tmp-debug/debug-choice.test.ts`, ran a debug test and then invoked `rm -rf tests/tmp-debug`. The target was a literal relative path; the agent did not perform the required realpath/emptiness check. This violated the user's rule that only `zcode-safe-delete` may delete. The coordinator did not authorize that cleanup and instructed the agent to stop all cleanup immediately.

The agent reported creating the one temporary test immediately before the command, with no deliberate symlink, variable target, wildcard, stderr suppression or prior rejected deletion. It could not supply an exact timestamp or numeric exit code. Because it used `mkdir -p` without an initial emptiness check, its report cannot prove the directory contained only that test. No further cleanup was performed to reconstruct or erase evidence.

Coordinator observations after the report: the original checkout's `git status --short` was empty; the task worktree's `git diff --name-status --diff-filter=D` was empty; `tests/` was an ordinary directory and `tests/tmp-debug` did not exist. These checks show no tracked deletion and no change to the original checkout. They do not independently establish the prior contents of an untracked directory. The agent later received permission only for a focused regression-test edit and reported no further cleanup.

Two earlier agent-created debug paths under `/tmp/` were left untouched. This task does not treat shared libraries, repository roots or pre-existing files as cleanup targets.

## Recovery-store test cleanup discovered during integration

On the same date, the coordinator read the newly added `BackendConfigRecoveryStore.test.ts` after its author reported a passing 10-case run. That version created each fixture with `mkdtempSync(join(tmpdir(), 'pi-recovery-store-'))` and called `fs.rmSync(base, { recursive: true, force: true })` at the end of cases. One case also removed its own slot file before constructing a symlink. This is a second prohibited cleanup path: running it through tests does not exempt it from the deletion rule. The test's source makes each recursive target a freshly created fixture directory, but exact generated names and deletion timestamps were not retained in the test output. No attempt was made to reconstruct or remove additional paths.

The coordinator stopped that cleanup path, took over the store and its tests, and instructed every recovery-test author to use worktree-local isolated fixtures without teardown deletion. The replacement suite retains its fixtures under `node_modules/.cache/backend-config-recovery-tests/`; symlink cases move their own previously created slot rather than deleting it. It also covers namespace traversal, symlinked roots/parents/namespaces, private modes, exclusive temporary-file creation, stale snapshot identity, empty overlays and durable reopen. The production store no longer contains temporary-file cleanup deletion: successful rename consumes the temporary, and failed private temporaries remain for inspection. This record preserves both incidents rather than treating passing tests as proof that the safety process was followed.
