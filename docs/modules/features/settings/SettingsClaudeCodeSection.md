# SettingsClaudeCodeSection

> **源码**: `src/features/settings/SettingsClaudeCodeSection.ts`
> **状态**: [REVIEW]

## 概述

`SettingsClaudeCodeSection` 负责 Claude Code backend 的 Phase A/Phase 2 设置面板。它通过 Claude Code 二级标签路由不同配置分组，暴露当前已有 adapter wiring 与测试覆盖的 runtime、模型思考、权限、上下文来源和工具策略；Claude-native Skills / Plugins / Agent Definitions 只允许作为 runtime/discovery/read-only 摘要进入设置表面，不提供 authoring。backend 启用仍由 `SettingsBackendSection` 负责，本 section 不注册 runtime，也不导入官方 Claude SDK。

## 职责

- 在 Runtime 标签渲染 restart-sensitive runtime boundary notice、Claude Code executable path、带只读状态标记的认证/环境提示、runtime diagnostics、env variables 的 runtime readback proof-status notice（two-layer boundary: this surface is `readback` supporting evidence for settings→SDK mapping; live behavior proof (env propagation, Layer 1-4) is verified in Capability Lab; overall capability: verified (pass)）、env variables 输入，以及从 active Claude adapter 回读的 runtime ecosystem 只读摘要（plugins / skills / agent definitions；只显示发现状态，不提供 authoring）。Runtime 标签还提供 `getRuntimeCatalog?.()`、`getAccountInfo?.()`、`getContextUsage?.()` 与 `readRuntimeFile?.()` 的只读 readback 操作：输出容器分别带 `data-claude-code-runtime-catalog="true"` / `data-claude-code-account-info-readback="true"` / `data-claude-code-context-usage-readback="true"` / `data-claude-code-file-readback="true"` 和 `data-proof-state="readback"`，只显示 sanitized catalog/JSON 或 runtime file supporting evidence；adapter 缺失、方法缺失、返回 null 或抛错时显示 unavailable/failure，不保存 settings，也不写 `.claude/**`。SDK `Query.getSettings()` 的 live settings snapshot readback 由 Capability Lab 的 Stable Settings Readback 子区承载；本稳定设置页不直接展示 snapshot，不写设置、不提供 MCP authoring，也不把 File Checkpoint / Rewind 或 Fallback Model 升格为行为通过
- 在 Model & Thinking 标签渲染 model、fallback model、thinking dropdown、thinking budget 和 effort dropdown；effort 选项与官方 Claude Code CLI/SDK 对齐为 low / medium / high / xhigh / max。主模型控件后渲染 `renderMainModelProofStatusNotice()`（compact proof-status notice，`data-proof-state="pass"`，标明 live model switching 有运行时证明确认：当活跃持久查询支持 `setModel()` 时，更改主模型立即生效；否则已保存模型应用于下一次查询。这不证明 fallback model switching）。该标签同时承载 max turns 和 max budget USD 限制控件，并在这些控件前渲染 limits proof-status notice（runtime behavior verified）和 limits boundary notice，提示这些设置只在下一次 query 生效并提供 restart 操作。fallback model 控件后依次渲染 `renderFallbackModelBoundaryNotice()`（提示 fallbackModel 需要重启/下一次查询才能生效）和 `renderFallbackModelProofStatusNotice()`（compact proof-status notice，`data-proof-state="readback"`，标明选项回读已运行时验证（SDK 源码确认 same-model validation + `--fallback-model` CLI 标志），但自动 fallback 切换无法本地验证——fallback triggers on API overload (HTTP 529)，不是 invalid-model errors；invalid-primary test 已失效：SDK 在 query boundary 接受任意 model 名称）。**同模型防护**：fallback model 文本输入和 quick-select 在用户选择的值与主模型相同时拒绝保存并显示 Notice 警告；主模型变更导致与 fallbackModel 匹配时自动清除 fallbackModel 并显示 Notice 通知。SDK 在 `ProcessTransport.initialize()` 中确定性拒绝 `fallbackModel === model`，插件侧的防护确保用户不会静默保存必然无效的配置
- model 保存时会通过当前注册的 Claude adapter 调用 `setModel()`，让活跃持久 query live 更新；Capability Lab 中的 `runSetModelLiveProbe()` 诊断 probe 已证明 `query.setModel()` 在持久查询 mid-stream 时成功切换模型。`renderMainModelProofStatusNotice()` 在 Model & Thinking 标签渲染 `data-proof-state="pass"` proof-status notice，诚实传达 live-apply 边界：有活跃持久查询时立即生效，否则已保存模型应用于下一次查询。没有活跃 query 或 adapter 不可用时仍只保存设置，下一次 query 会读取新值。**这不证明 fallback model switching**（见 fallback model proof-status notice）
- Model & Thinking 标签在 model / fallbackModel 文本输入下方各渲染一个 `renderModelQuickSelect()` / `renderFallbackModelQuickSelect()` 下拉框。下拉框在标签渲染时自动通过当前 Claude adapter 异步调用 `supportedModels()` 加载可用模型目录；用户从下拉框选择模型后，会自动更新上方的文本输入值并保存设置（主模型还会尝试 live apply）。该设计将目录发现与字段输入收敛为统一的 quick-select 体验，既保留文本输入的自由度（支持自定义模型名），又让用户不必仅靠 placeholder 猜测合法模型 ID。目录结果在实例级别缓存，避免重复请求
- adaptive / disabled thinking 下不渲染 thinking budget，避免显示不会生效的空编辑控件；fixed thinking 下保留用户已有 budget
- 在 Permissions 标签渲染 permission mode dropdown 和 sandbox 行为控制（`enabled`、`failIfUnavailable`、`autoAllowBashIfSandboxed` 三个 toggle）；sandbox 设置控制子进程是否在 OS sandbox 中运行，不等于文件系统或网络权限规则编辑器。保存 permission mode 时会通过 Claude adapter 调用 `setPermissionMode()` 尝试更新活跃 query；sandbox 设置在下次 query 时生效，不可 live-apply 到正在运行的会话，sandbox 块有独立的 next-query lifecycle notice 声明此限制
- 在 Context & Sources 标签渲染 setting sources toggles（user/project/local）、项目来源文件可见性（`CLAUDE.md`、`.claude/settings.json`、`.claude/settings.local.json`）、restart-sensitive runtime boundary notice 和 additional directories textarea
- Runtime 与 Context & Sources 标签都提供 “Restart sessions” 操作，调用 Claude adapter 的 `restartPersistentQueries('settings-change')`，只关闭活跃持久 query，不删除 session；下一次发送会用最新 source/directory/env/tool/limit options 重新启动并在可能时 resume
- 在 Tools 标签渲染 restart-sensitive runtime boundary notice、MCP runtime 只读状态、刷新按钮、SDK `mcpServerStatus()` runtime status readback 按钮、allowed/disallowed tools 的 runtime readback verified proof-status notice，以及 allowed/disallowed tools 输入；MCP 控制只调用当前 Claude adapter 的 `getMcpServerCount()` / `getMcpServerNames()` / `getMcpServerRuntimeStatuses()` / `reloadMcpServers()`。有已加载 server 名称时只读展示名称；用户点击 Inspect runtime status 时只读显示 connected/failed/tool names/error summary，标记 `data-proof-state="readback"`。这些路径都不写入 `.claude/mcp.json`，刷新失败或 status readback 失败会保留明确错误状态
- Max turns 和 max budget USD 输入必须是完整正数，`12abc` / `5usd` 这类部分数字会归一化为 unlimited/null，空白仍保持 unlimited/null
- Account info readback 使用防御性 JSON 格式化；`email` 会遮罩为 `u***@example.com` 这类形式，`apiKeySource` / `tokenSource` / token / secret / credential / authorization / oauth / env 等凭据相关 key 显示 `[redacted]`。该按钮只读取 SDK `Query.accountInfo()` 报告的认证摘要，不执行登录、不保存 settings、不改变 backend enablement
- Context usage readback 使用防御性 JSON 格式化；key 名匹配 `env` / `apiKey` / `secret` / `password` / `credential` / `authorization` / `oauth` 或凭据类 token（例如 `accessToken` / `refreshToken` / `sessionToken` / `authToken` / 独立 `token`）时统一显示 `[redacted]`，但 `tokenEstimate` / token count 等普通用量字段会保留；同时处理 null、BigInt、函数/undefined 与循环引用，避免把 secret 或不可序列化对象直接暴露到设置页
- Runtime catalog readback 使用 `Inspect runtime catalog` 触发 active Claude adapter 的 `getRuntimeCatalog()`；只展示 SDK `supportedCommands()` / `supportedAgents()` 回读到的 slash command 名称、描述、argument hint、aliases，以及 agent 名称、描述、model。输出保持 `data-proof-state="readback"`，不执行 slash command、不创建/编辑 agent、不保存设置、不写 `.claude/**`，也不证明 command execution 或 agent authoring 行为
- Runtime file readback 使用路径输入触发 active Claude adapter 的 `readRuntimeFile()`；当前 Settings UI 默认请求 `maxBytes: 4096` 且 `encoding: 'utf-8'`，adapter/SDK 可支持 `base64`。设置页只展示 SDK 回传的 `absPath`、`contents` 与 `truncated` 等 readback 字段，截断时显示明确提示；空路径、adapter 方法缺失或返回 null 都保持 `readback` 状态并显示对应提示。该按钮不保存设置、不写文件、不 bypass permissions、不写 `.claude/**`，也不证明 File Checkpoint / Rewind 或 Fallback Model 行为
- Environment variables 输入通过 `parseEnv()` 解析，只接受标准 POSIX 键名（`[A-Za-z_][A-Za-z0-9_]*`），含空格、连字符或以数字开头的键会被静默丢弃；值部分保留trim后的原始内容
- Allowed/disallowed tools 输入通过 `parseToolList()` 解析，只接受 PascalCase 字母数字工具名（`[A-Za-z][A-Za-z0-9]*`），含空格、连字符或以数字开头的名称会被静默丢弃；runtime readback verified（Stable Settings Readback Proof 确认 options.allowedTools / options.disallowedTools 从设置正确构建）
- SDK Foundations 标签已移除；file checkpoint 开关（`enableFileCheckpointing`）和 hook event stream / forward subagent transcript / subagent progress summaries 等诊断流开关仍属于 Debug → Capability Lab 诊断边界。runtime ecosystem 摘要（Plugins / Skills / Agent Definitions）已经产品化为 Claude Code settings 的只读发现表面：只展示 adapter 回读到的数量、名称和 `skills: "all"` 等 sentinel，不写 `.claude/**` 配置、不创建/编辑条目，也不把 read-only 摘要包装成 authoring。File Checkpoint / Rewind 与 Fallback Model 仍分别保持 readback/blocker 口径，不随该摘要升格
- 将多标签设置输入写入 `settings.backendSettings.claudeCode`
- 通过 `ClaudeCodeProcessResolver` 做本地进程解析诊断，帮助检查 bundled/default resolution 与外部 CLI path
- 新增 `renderMainModelProofStatusNotice()`、`renderToolsProofStatusNotice()`、`renderLimitsProofStatusNotice()`、`renderFallbackModelProofStatusNotice()`、`renderEnvProofStatusNotice()` 和 `renderRestrictedBuiltinToolsProofStatusNotice()` 六个 compact proof-status notice 方法，在对应标签中渲染 runtime proof status；main-model 使用 `data-proof-state="pass"`（live model switching verified — 当活跃持久查询支持 `setModel()` 时模型切换立即生效；否则已保存模型应用于下一次查询。这不证明 fallback model switching），tools 使用 `data-proof-state="readback"`（pre-allow / auto-approve shortcut, not restrictor — zero enforcement: init catalog always unfiltered, canUseTool dead in SDK query() mode；use Restricted Built-in Tools for deterministic built-in filtering），env 使用 `data-proof-state="readback"`（settings→SDK mapping = readback supporting evidence only；live behavior proof (env propagation into Bash subprocess, Layer 1-4) is verified in Capability Lab; overall capability: verified (pass)），limits 使用 `data-proof-state="pass"`（runtime behavior verified — maxTurns 和 maxBudgetUsd enforcement 已通过 live runtime proof 确认），fallback model 使用 `data-proof-state="readback"`（选项回读已运行时验证 + SDK 源码确认 same-model validation，自动 fallback 切换无法本地验证：fallback triggers on API overload (HTTP 529)，invalid-primary test 已失效——SDK 在 query boundary 接受任意 model 名称。Switching behavior not locally provable），restricted-builtin-tools 使用 `data-proof-state="pass"`（runtime deterministic at init tool-catalog level via real settings wiring proof — built-in only, MCP unaffected），file-checkpointing 使用 `data-proof-state="readback"`（experimental / diagnostic-only — SDK option wired but checkpoints never created in query() mode due to upstream bug #236; no stable rewind UI or restore action; toggle and dry-run preview in Capability Lab）；样式位于 `src/style/components/settings-claude-code.css`，使用 `data-proof-state` 和 `data-claude-code-proof-status` 选择器
- File Checkpoint / Rewind boundary notice 只在 Runtime 标签中渲染只读 boundary status；`enableFileCheckpointing` toggle 位于 Capability Lab 的 Diagnostic Stream Controls 子区，不在稳定设置中暴露
- 保持 hook authoring、skills/plugins authoring、agent-definition authoring、external SessionStore、JSONL import/browser 等未完成能力不在 UI 中暴露，直到对应 phase 有端到端 runtime proof；Skills / Plugins / Agent Definitions 的只读 runtime ecosystem 摘要是例外边界，它只能显示发现状态，不能写入配置或提供 authoring 操作

## 公共导出

- `SettingsClaudeCodeSection`: 构造参数包含 `plugin`、`createSectionHeading()`，以及测试/诊断可注入的 `resolveProcess()`。`attach()` 用于 classic 设置页，`attachTabbed()` 用于 tabbed 设置页。

## 集成

- `OpenCodianSettings`: classic 设置页在 General 后挂载本 section
- `OpenCodianSettingsView`: editor-area classic 设置页复用本 section
- `SettingsTabbedRenderer`: `claude-code/runtime`、`claude-code/model-thinking`、`claude-code/permissions`、`claude-code/context-sources`、`claude-code/tools` 标签路由到本 section
- `settingsLayoutRegistry`: 声明 `claude-code` 配置标签，但不设置 `backendRequired`
- `ClaudeCodeProcessResolver`: runtime diagnostics 按当前 Claude settings 解析 process mode

## 维护约束

- 该 section 是 Phase A 多标签设置 surface；不要把 SDK option builder 支持的字段等同于已经可以给用户操作的产品能力
- 所有实验性/诊断性控制（hook/subagent stream、file checkpointing、runtime ecosystem 摘要）已移至 Capability Lab；稳定设置只保留有真实用户界面效果或 runtime readback verified 的控制
- 新增或调整 Claude Code 二级标签时，同步 `renderTabContent()` 路由、classic `attach()` 分组、settings layout registry、locale 文案、稳定 `data-settings-target` / `data-claude-code-section` 属性和测试覆盖
- 该 section 不应直接依赖 `@anthropic-ai/claude-agent-sdk`；真实 SDK runtime 由 `ClaudeCodeAdapter` / `ClaudeCodeSdkLoader` 负责
- 所有文案必须通过 locale key 获取
- 修改字段时同步 `src/core/types/settings.ts` 的默认值/normalizer 和 `SettingsClaudeCodeSection.test.ts`
