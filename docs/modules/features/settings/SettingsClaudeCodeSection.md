## 概述

### 2026-07-23 当前契约（取代下方历史的 model/fallback 叙述）

`SettingsClaudeCodeSection` 现在只注册并调度 Claude 二级标签。`providers` 交给 `SettingsClaudeProvidersSection`；`model-thinking` 仅保留 thinking / fixed budget / effort；query limits 与 prompt behavior 位于 `runtime`；`tools` 仅有 tool policy + question UX；`mcp` 独立承载 MCP runtime；`skills-commands` 与 `agents` 分别以资源种类过滤渲染。旧 plugin model/fallback 编辑器、quick-select 和对 active query 的 `setModel()` 调用已移除。Provider 文件改动在新 query 或重启会话后生效；聊天内显式模型选择仍保持会话 override 语义。

`SettingsClaudeCodeSection` 负责 Claude Code backend 的 Phase A/Phase 2 设置面板。它通过 Claude Code 二级标签路由不同配置分组，暴露当前已有 adapter wiring 与测试覆盖的 runtime、thinking/effort、权限、上下文来源、工具策略与 provider/resource 子页；每个 tab body 现在带 `data-settings-surface="tab-body"`，并将控件包进稳定的 `data-claude-code-group` 语义组。每个组都有 `opencodian-claude-code-group-header`、`opencodian-claude-code-group-title`、`opencodian-claude-code-group-desc` 与内部 `opencodian-claude-code-stack`，方便样式、测试和运行时证明口径对齐。**卡片层级约束**：`data-claude-code-group` 容器本身是**扁平语义分组**（仅 margin + 标题 + 描述，无 border/bg/radius），card base 只作用到组 stack 内的 `setting-item` / notice strip / readback / proof-status 上，最终视觉层级严格保持 `section-card → setting-item-card` 两层，与 Codex 设置表面一致（避免"卡片套卡片"）。2026-06-28 起，Claude Code 行级控件采用紧凑 control-surface 布局：桌面为 `label/description` + `control` 双列，控件列可换行，textarea 保持稳定宽度；720px 以下折叠为单列，避免按钮或长输入挤压说明文字。`renderRuntimeBoundaryNotice()` / `renderLimitsBoundaryNotice()` 现在把 boundary notice strip 与 restart Setting 作为**平级**元素放进组 stack（通过共享的 `renderBoundaryNoticeAndRestart()`），不再把 Setting 嵌进 notice div，从而消除 4 层嵌套。

模型选择区还提供共享“成本估算”入口。Claude Code 只有终态 `result` usage 产生可计费 ledger 后才会使用本地 prices 估算 input/output/reasoning/cache；该值是 API 等价估算，不能描述为 Claude 订阅账单。默认按流式模型 ID 自动匹配 models.dev；只有第三方 gateway 的价格不同或 model ID 有歧义时，才填写可选的 Provider ID / 计费 Base URL，它们不会改写 `ANTHROPIC_BASE_URL`。

**说明文字密度约束**：默认只暴露可配置项；boundary / lifecycle / proof-status 说明文字不再渲染为独立 strip，而是通过 `attachSettingHelp(setting, {...})` 收进 setting 行末尾的 `help-circle` 按钮 —— 短文（lifecycle）进 tooltip 即时可见，长文（boundary + proof）进点击打开的 `ClaudeCodeHelpModal`。proof-status（pass/readback）进一步降级为 setting 控件旁的 10px 色点 chip（`attachProofChip`），绿=pass、蓝=readback，tooltip 显示证据。**组级描述**也收进 `createClaudeCodeGroup` 渲染的标题旁 help 按钮（`opencodian-claude-code-group-help-button`，hover 显示组描述），不再渲染整行 `<p>` 描述段落。为维持测试与无障碍访问，`attachSettingHelp`、组 help 按钮和 proof chip 都挂 sr-only `opencodian-claude-code-notice-text` carrier span，并以 `aria-labelledby` 引用它；不得在 `data-settings-tooltip` 触发器上保留 `title` 或 `aria-label`，否则 Obsidian 会在自定义气泡之后再显示原生延迟 tooltip。`renderTabContent` 调用 `SettingsTooltipController.ensureForDocument` 激活共享 tooltip 控制器。readback / scan-output / diagnostics 数据卡（带实时数据）**保持不动**；runtimeBoundary restart strip（带功能按钮）也保留为内联控件。Claude-native Skills / Plugins / Agent Definitions 只允许作为 runtime/discovery/read-only 摘要进入设置表面，不提供 authoring。**项目级配置**：Runtime 标签现在提供项目 agents（`.claude/agents/*.md`）和项目 settings（`.claude/settings.json` / `.claude/settings.local.json`）的 scan/create/open 操作——项目 settings 表面解析 `hooks`、`enabledPlugins` 和 `extraKnownMarketplaces` 字段，用户通过 Open 按钮在编辑器中直接编辑这些 JSON 文件（官方路径），而非通过可视化编辑器。backend 启用仍由 `SettingsBackendSection` 负责，本 section 不注册 runtime，也不导入官方 Claude SDK。

## 职责

- 在 Runtime 标签按固定语义组渲染：`connection-runtime`（runtime boundary、executable path、JavaScript runtime、load timeout、environment hint）、`runtime-ecosystem`（runtime ecosystem readback 与 browse-only backend session browser）、`project-files`（project skills / commands / agents / settings）、`runtime-inspection`（runtime commands、runtime catalog、account info、context usage、runtime file readback）以及 `diagnostics-logs`（diagnostics、debug toggle、debug file、env proof/readback、file checkpoint boundary 和 env variables）。从 active Claude adapter 回读的 runtime ecosystem 只读摘要（plugins / skills / agent definitions；只显示发现状态，不提供 authoring）和 `getRuntimeCatalog?.()`、`getAccountInfo?.()`、`getContextUsage?.()`、`readRuntimeFile?.()` 输出都带 `data-proof-state="readback"` 与 `opencodian-settings-readback` / `opencodian-claude-code-readback`，只显示 sanitized catalog/JSON 或 runtime file supporting evidence；adapter 缺失、方法缺失、返回 null 或抛错时显示 unavailable/failure，不保存 settings，也不写 `.claude/**`。Runtime 标签还提供项目技能和运行时命令 discovery 控件：`renderClaudeProjectSkillsControls()` 调用 adapter `getProjectClaudeSkills()` 扫描 vault `.claude/skills/<name>/SKILL.md` 并显示名称、描述和相对路径，同时提供 Create skill 按钮和 per-entry Open 按钮；`renderClaudeRuntimeCommandsControls()` 调用 `getRuntimeCatalog()` 只读列出 SDK `supportedCommands()` 返回的 command、description 和 argument hint。`renderClaudeProjectCommandsControls()` 直接导入 `ClaudeProjectCommandDiscovery` 扫描 vault `.claude/commands/*.md` 并显示命令名称、描述和路径，同时提供 Create command 按钮和 per-entry Open 按钮。这两组输出分别使用 `data-claude-code-project-skills="true"` 与 `data-claude-code-runtime-commands="true"`，不执行命令、不写 `.claude/**`、不提供 skills/commands authoring。SDK `Query.getSettings()` 的 live settings snapshot readback 由 Capability Lab 的 Stable Settings Readback 子区承载；本稳定设置页不直接展示 snapshot，不写设置、不提供 MCP authoring，也不把 File Checkpoint / Rewind 或 Fallback Model 升格为行为通过
- `renderBackendSessionBrowserInfo()` 现在在 Runtime 标签提供真实 browse-only launcher，而不是只读说明文本：它渲染 “Browse Sessions” 按钮，打开 `BackendSessionBrowserModal`，并以 `supportsResume: () => false` 隐藏 Resume 按钮；下方 browse-only notice 明确恢复会话需要 active chat view。
- 在 Model & Thinking 标签按 `model-selection`、`thinking-effort`、`limits-budget`、`prompt-behavior` 四组渲染。`model-selection` 包含 model、fallback model、quick-select 和主模型/fallback proof notice；`thinking-effort` 包含 thinking dropdown、fixed budget（仅 fixed 时出现）和 effort dropdown；`limits-budget` 包含 limits proof/boundary、max turns、max budget USD 和 task budget；`prompt-behavior` 包含 appended instructions、output style、prompt suggestions 和 1M 上下文 beta。主模型控件后渲染 `renderMainModelProofStatusNotice()`（compact proof-status notice，`data-proof-state="pass"`，标明 live model switching 有运行时证明确认：当活跃持久查询支持 `setModel()` 时，更改主模型立即生效；否则已保存模型应用于下一次查询。这不证明 fallback model switching）。fallback model 控件后依次渲染 `renderFallbackModelBoundaryNotice()` 和 `renderFallbackModelProofStatusNotice()`（`data-proof-state="readback"`，标明选项回读已运行时验证但自动 fallback 切换无法本地验证）。**同模型防护**：fallback model 文本输入和 quick-select 在用户选择的值与主模型相同时拒绝保存并显示 Notice 警告；主模型变更导致与 fallbackModel 匹配时自动清除 fallbackModel 并显示 Notice 通知。
- model 保存时会通过当前注册的 Claude adapter 调用 `setModel()`，让活跃持久 query live 更新；Capability Lab 中的 `runSetModelLiveProbe()` 诊断 probe 已证明 `query.setModel()` 在持久查询 mid-stream 时成功切换模型。`renderMainModelProofStatusNotice()` 在 Model & Thinking 标签渲染 `data-proof-state="pass"` proof-status notice，诚实传达 live-apply 边界：有活跃持久查询时立即生效，否则已保存模型应用于下一次查询。没有活跃 query 或 adapter 不可用时仍只保存设置，下一次 query 会读取新值。**这不证明 fallback model switching**（见 fallback model proof-status notice）
- Model & Thinking 标签在 model / fallbackModel 文本输入下方各渲染一个 `renderModelQuickSelect()` / `renderFallbackModelQuickSelect()` 下拉框。下拉框在标签渲染时自动通过当前 Claude adapter 异步调用 `supportedModels()` 加载可用模型目录；用户从下拉框选择模型后，会自动更新上方的文本输入值并保存设置（主模型还会尝试 live apply）。该设计将目录发现与字段输入收敛为统一的 quick-select 体验，既保留文本输入的自由度（支持自定义模型名），又让用户不必仅靠 placeholder 猜测合法模型 ID。目录结果在实例级别缓存，避免重复请求
- adaptive / disabled thinking 下不渲染 thinking budget，避免显示不会生效的空编辑控件；fixed thinking 下保留用户已有 budget
- 在 Permissions 标签按 `permission-mode`、`plan-mode`、`sandbox-core`、`sandbox-advanced` 四组渲染。`sandbox-core` 保留 sandbox boundary notice 与核心开关：`enabled`、`failIfUnavailable`、`autoAllowBashIfSandboxed`；`sandbox-advanced` 带 `data-claude-code-advanced-sandbox="true"`、`opencodian-settings-advanced-sandbox`、`opencodian-claude-code-advanced` 和 `opencodian-claude-code-advanced-summary`，视觉上弱化命令例外、unsandboxed 命令允许列表、filesystem/network 子策略、weaker nested/network isolation 开关，以及 ripgrep command/args override。保存 permission mode 时会通过 Claude adapter 调用 `setPermissionMode()` 尝试更新活跃 query；plan mode instructions 与 sandbox 设置在下次 query 时生效，不可 live-apply 到正在运行的会话，两者均有独立的 next-query lifecycle notice 声明此限制。sandbox 稳定设置 boundary notice 继续以 "Readback only" 开头，声明插件只能传递选项、无法独立验证实际 OS-level sandbox 强制执行
- 在 Context & Sources 标签按 `source-activation`、`project-source-files`、`additional-context` 三组渲染 setting sources toggles（user/project/local）、项目来源文件可见性（`CLAUDE.md`、`.claude/settings.json`、`.claude/settings.local.json`）、restart-sensitive runtime boundary notice 和 additional directories textarea
- Runtime 与 Context & Sources 标签都提供 “Restart sessions” 操作，调用 Claude adapter 的 `restartPersistentQueries('settings-change')`，只关闭活跃持久 query，不删除 session；下一次发送会用最新 source/directory/env/tool/limit options 重新启动并在可能时 resume
- 在 Tools 标签按 `mcp-runtime`、`tool-policy`、`question-ux` 三组渲染。`mcp-runtime` 包含 restart-sensitive runtime boundary notice、MCP runtime 只读状态、刷新按钮、SDK `mcpServerStatus()` runtime status readback 按钮和 strict MCP config toggle；`tool-policy` 包含 tools proof、allowed/disallowed/restricted built-in tools、restricted built-in proof 和 tool aliases；`question-ux` 单独承载 AskUserQuestion preview format 下拉选择。MCP 控制只调用当前 Claude adapter 的 `getMcpServerCount()` / `getMcpServerNames()` / `getMcpServerRuntimeStatuses()` / `reloadMcpServers()`。有已加载 server 名称时只读展示名称；用户点击 Inspect runtime status 时只读显示 connected/failed/tool names/error summary，标记 `data-proof-state="readback"` 和 `opencodian-settings-readback` / `opencodian-claude-code-readback`。这些路径都不写入 `.claude/mcp.json`，刷新失败或 status readback 失败会保留明确错误状态。`allowedTools` 设置继续带 `data-claude-code-allowed-tools-boundary="true"` 边界提示，明确声明 Readback only、零 enforcement 证据，并引导用户改用 Restricted Built-in Tools 进行确定性内置工具过滤。
- Max turns、max budget USD 和 task budget 输入必须是完整正数，`12abc` / `5usd` 这类部分数字会归一化为 unlimited/null，空白仍保持 unlimited/null。task budget 使用整数解析（同 maxTurns），不接受小数。taskBudget 分类为 readback（2026-06-06 审计硬化 + re-audit Outcome B）：选项连接已验证，以 `--task-budget` CLI 标志传递给子进程，CLI 作为 `output_config.task_budget` 连同 beta header 发送给 API。模型用作行为 pacing（非硬性截止），没有结构化 enforcement 信号（无 `error_max_task_budget` result subtype，无 budget-related `TerminalReason`，无 budget event types）。@alpha。与 `maxTurns`/`maxBudgetUsd`（有确定性 enforcement signal 的 pass/verified seams）语义不同，不可复用其 proof。loadTimeoutMs 分类为 readback（2026-06-06 审计硬化）：选项连接已验证，但 SDK 仅在 sessionStore resume/continue 路径使用此超时，诊断路径无法触发。@alpha。
- Account info readback 使用防御性 JSON 格式化；`email` 会遮罩为 `u***@example.com` 这类形式，`apiKeySource` / `tokenSource` / token / secret / credential / authorization / oauth / env 等凭据相关 key 显示 `[redacted]`。该按钮只读取 SDK `Query.accountInfo()` 报告的认证摘要，不执行登录、不保存 settings、不改变 backend enablement

## 公共导出

- `SettingsClaudeCodeSection`: 构造参数包含 `plugin`、`createSectionHeading()`，以及测试/诊断可注入的 `resolveProcess()`。`attach()` 用于 classic 设置页，`attachTabbed()` 用于 tabbed 设置页。
- `ClaudeCodeRuntimeEcosystemAdapter`（内部窄化接口）现在包含 `getProjectClaudeSkills?()`；Runtime 标签通过该方法扫描项目 `.claude/skills`，并继续通过 `getRuntimeCatalog?()` 展示 Claude runtime commands。
- **Batch 2 新增**: Runtime 标签现在提供项目技能 create + open 操作（`handleCreateClaudeProjectSkill` + `openFileInEditor`），项目命令 discovery + create + open 操作（`renderClaudeProjectCommandsControls` + `handleCreateClaudeProjectCommand`）。项目命令通过直接导入 `ClaudeProjectCommandDiscovery` 而非通过 `ClaudeCodeAdapter`，避免 owner-guard 耦合。`getVaultBasePath()` 和 `openFileInEditor()` 是共享 helper 方法。
- **Batch 3 新增**: Runtime 标签现在提供项目 agents（`renderClaudeProjectAgentsControls`）和项目 settings/hooks+plugins（`renderClaudeProjectSettingsControls`）的 scan/create/open 操作。项目 settings 使用 `ClaudeProjectSettingsDiscovery` 直接动态导入，解析 `hooks`、`enabledPlugins` 和 `extraKnownMarketplaces`，以文件发现和编辑器打开方式提供官方路径入口，不实现可视化 hook/plugin 编辑器。`ClaudeCodeRuntimeEcosystemAdapter` 新增 `getProjectClaudeAgents?()` 方法。
- **2026-06-06 新增**: `renderBackendSessionBrowserInfo()` 导入并打开 `BackendSessionBrowserModal`，以 `supportsResume: false` 的 host 提供 settings 侧 browse-only session inspection；对应 locale key 使用 `settings.claudeCode.sessionBrowser.launch*` 与 `browseOnlyNotice`。

## 维护约束

- 该 section 是 Phase A 多标签设置 surface；不要把 SDK option builder 支持的字段等同于已经可以给用户操作的产品能力
- 所有实验性/诊断性控制（hook/subagent stream、file checkpointing、runtime ecosystem 摘要）已移至 Capability Lab；稳定设置只保留有真实用户界面效果或 runtime readback verified 的控制
- 新增或调整 Claude Code 二级标签时，同步 `renderTabContent()` 路由、classic `attach()` 分组、settings layout registry、locale 文案、稳定 `data-settings-target` / `data-claude-code-section` 属性和测试覆盖
- 该 section 不应直接依赖 `@anthropic-ai/claude-agent-sdk`；真实 SDK runtime 由 `ClaudeCodeAdapter` / `ClaudeCodeSdkLoader` 负责
- 所有文案必须通过 locale key 获取
- 修改字段时同步 `src/core/types/settings.ts` 的默认值/normalizer 和 `SettingsClaudeCodeSection.test.ts`
- Runtime / permissions / context / tools textareas that expose manual resize use `TextareaSizeMemory` with stable keys, and `dispose()` cleans the attached observers when the section is rebuilt.
- 2026-06-06 session browser launcher：`renderBackendSessionBrowserInfo()` 从 read-only notice 升级为 browse-only modal launcher；settings 侧 host 必须保持 `supportsResume: false`，避免在无聊天视图上下文时创建或恢复 conversation。
